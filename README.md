# AI Radar — каталог нових AI-сайтів (React)

Тестове завдання для вакансії Junior AI Web Developer. Невеликий робочий веб-проєкт на React, який працює з публічним API **freeserp.ai** (без ключа та реєстрації): індекс `sites` (головні сторінки сайтів), ніша AI.

Додатково в проєкті є коротка схема сайту: мета, аудиторія, сторінки та структура — файл [`PLAN.md`](./PLAN.md).

---

## 1. Ідея

**AI Radar** — каталог нових AI-сайтів, які щойно запрацювали. Користувач може:

- шукати сайти за текстом;
- обирати нішу (Image Generation, AI Agents, Code & Dev Tools тощо);
- сортувати за свіжістю, авторитетом (Domain Rating) або релевантністю;
- обмежувати період запуску та мінімальний DR;
- позначати до трьох сайтів і порівнювати їх у таблиці.

Це поєднує дві ідеї із завдання: каталог із фільтрами та порівняння сайтів, плюс добірка новинок (за замовчуванням показано сайти, що запустились за останні 7 днів).

## 2. Що зроблено

### Функціонал
| Можливість | Як реалізовано |
|---|---|
| Пошук | Поле `q`, запит відправляється з затримкою 350 мс (debounce) |
| Фільтр за нішею | Випадаючий список; ніші беруться з `?stats=1`, є запасний статичний список із документації |
| Сортування | «Найновіші» (`went_live`), «Найавторитетніші» (`dr`), «За релевантністю» |
| Період запуску | 7 / 30 / 90 днів або весь час (`from_date`) |
| Мінімальний DR | Числове поле 0–100, значення обмежується перед відправкою (`dr_min`) |
| Лише справжні AI-продукти | Завжди `ai_startups=1`, як рекомендує документація |
| Лічильники в шапці | «AI-стартапів в індексі» та «нових сьогодні» з `?stats=1` |
| Пагінація | Кнопка «Показати ще» (`size=20`, `from`), з урахуванням ліміту 10 000 |
| Порівняння | Чекбокс у рядку, до 3 сайтів, нижня панель і модальне вікно з таблицею |
| Темна/світла тема | За системою, плюс кнопка «Тема» |

### Поля, які показуються для кожного сайту
Назва (`title`), домен, AI-опис (`ai_summary`), ніші (`ai_categories`), стек/білдер (`ai_source`), Domain Rating (`dr`, також як вертикальна шкала зліва), дата запуску (`went_live`), зона (`tld`) у порівнянні.

### Стани інтерфейсу
- завантаження;
- порожній результат (підказка, що змінити у фільтрах);
- помилка мережі/API з кнопкою «Повторити»;
- повідомлення, коли обрано вже 3 сайти для порівняння;
- кнопка «Порівняти» неактивна, поки не обрано щонайменше 2 сайти.

### Якість і безпека
- Дані з API виводяться як текст через React (без `dangerouslySetInnerHTML`), тому HTML з API не виконується.
- Посилання перевіряються: дозволено лише `http://` та `https://`, відкриваються з `rel="noopener noreferrer"`.
- Попередній запит скасовується через `AbortController`, тому застарілі відповіді не перезаписують свіжі.
- Доступність: підписані поля, видимий фокус, `aria-live` для списку, нативний `<dialog>` (фокус і Esc працюють з коробки), `aria-label` для чекбоксів.
- Адаптивна верстка (таблиця порівняння прокручується по горизонталі на вузьких екранах).
- До запитів додано необов'язкові `agent` і `project`, як радить документація API.

## 4. Структура проєкту

```
ai-radar-react/
├─ index.html                 # точка входу Vite
├─ package.json
├─ vite.config.js             # base: "./" — збірку можна класти в будь-яку підпапку
├─ PLAN.md                    # план сайту: мета, аудиторія, сторінки, структура
├─ README.md                  # цей файл
├─ dist/                      # готова збірка (npm run build)
└─ src/
   ├─ main.jsx                # монтування React
   ├─ App.jsx                 # стан застосунку, склад сторінки
   ├─ api.js                  # робота з API: побудова параметрів, fetch, константи
   ├─ utils.js                # safeUrl, форматування дат і чисел
   ├─ styles.css              # уся стилізація, світла/темна теми
   ├─ hooks/
   │  ├─ useDebounce.js       # затримка для введення
   │  ├─ useSites.js          # завантаження списку, догрузка, помилки, скасування запитів
   │  └─ useStats.js          # лічильники та список ніш з ?stats=1
   └─ components/
      ├─ Filters.jsx          # панель фільтрів
      ├─ SiteRow.jsx          # рядок сайту (мемоізований)
      ├─ CompareBar.jsx       # нижня панель порівняння
      └─ CompareDialog.jsx    # модальне вікно з таблицею порівняння
```

### Як усе пов'язано
- `App.jsx` тримає стан фільтрів, обрані для порівняння сайти, тему та видимість діалогу.
- Фільтри проходять через `useDebounce`, і вже стабілізоване значення потрапляє в `useSites`.
- `useSites` при зміні фільтрів скидає список і робить новий запит, а `loadMore` додає наступну порцію (`from` = кількість уже завантажених).
- `useStats` один раз завантажує статистику й список ніш.
- `api.js` — єдине місце, яке знає про формат запитів до API.

## 5. Використання API

Базовий адрес: `GET https://freeserp.ai/api.php` (індекс `sites` за замовчуванням).

| Потреба інтерфейсу | Параметр |
|---|---|
| Лише AI-продукти | `ai_startups=1` |
| Пошук | `q` |
| Ніша | `ai_categories` |
| Сортування | `sort` (`went_live`, `dr`, `relevance`), `order=desc` |
| Період запуску | `from_date=YYYY-MM-DD` |
| Мінімальний DR | `dr_min` |
| Розмір сторінки / зміщення | `size=20`, `from` |
| Статистика | `stats=1` |

Приклад запиту, який формує застосунок:

```
https://freeserp.ai/api.php?ai_startups=1&size=20&from=0&sort=went_live&order=desc&agent=ai-radar%2F1.0&project=AI+Radar+test+task&from_date=2026-09-25
```

### Особливості, враховані з документації
- `went_live` — це дата, коли сайт вперше підтвердили як робочий, а не офіційний запуск; про це сказано у підвалі.
- `dr` у нових доменів може бути порожнім — тоді показується «—».
- Індекс `sites` — це перевірка нових сайтів, старі великі сайти там можуть бути відсутні.
- Для `from + size` діє ліміт 10 000, його враховано в кнопці «Показати ще».

## 6. Як запустити

Потрібен Node.js 18+ та доступ до інтернету.

```bash
npm install
npm run dev        # режим розробки, http://localhost:5173
npm run build      # продакшн-збірка в папку dist
npm run preview    # локальний перегляд збірки
```

Папку `dist` не можна відкривати подвійним кліком як `file://` (браузери блокують модульні скрипти), її потрібно віддавати через сервер: `npm run preview`, `npx serve dist`, GitHub Pages, Netlify, Vercel.

---

## 7. Що перевірено, а що ні

- Перевірено: проєкт встановлюється та збирається без помилок (`npm run build`).
- Не перевірено: живі запити до freeserp.ai. Середовище, де створювався проєкт, не мало доступу до цього домену, тому формат відповіді взято з офіційної документації. Перед здачею варто відкрити `npm run dev` і пройтися по фільтрах на живих даних.

## 8. Ідеї для розвитку
- Зберігати фільтри в адресному рядку (щоб ділитися посиланням на добірку).
- Зберігати обрані сайти у `localStorage`.
- Додати окрему сторінку сайту з повним описом і текстом головної (`content=1`).
- Додати пошук по всьому вебу через `index=web`.
